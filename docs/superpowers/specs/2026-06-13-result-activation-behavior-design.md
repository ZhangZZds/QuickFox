# 搜索结果激活行为设计

## 背景

QuickFox 搜索结果由 Rust core 返回统一的 `mainAction` 和 `secondaryActions`。当前结果行支持鼠标悬停选中和右键菜单，但左键单击不会执行主动作；Enter 只在搜索输入框聚焦时执行当前选中项。

## 目标

- 左键单击结果行立即执行该结果的主动作。
- Enter 执行当前选中结果的同一主动作。
- 文件夹、文件、应用、网页搜索、计算器、命令等结果类型继续由 Rust core 返回的 `mainAction` 决定行为。
- 文件和目录打开保持跨平台：前端只调用动作，Rust core/Tauri opener 交给系统默认应用或文件管理器处理。
- 右键菜单继续只提供次要动作，不执行主动作。

## 方案

采用统一激活入口。前端提炼 `activateResult(result)`，左键单击和 Enter 都调用它；该函数只执行 `result.primaryAction` 并记录输入历史。前端不根据 `kind`、扩展名或平台判断文件应该如何打开。

不采用前端按类型分支。这样可以避免在 TypeScript UI 层复制 Rust Provider 的动作语义，也避免跨平台默认应用规则散落在前端。

## 测试

- 文件结果：左键单击执行 `openPath`。
- 目录结果：左键单击执行 `openPath`。
- 应用结果：左键单击执行 `openPath`。
- 同一结果：Enter 和左键单击执行同一主动作。
- 右键菜单：右键打开菜单但不执行主动作。

## 风险

- 单击即执行会提高误点成本，但这是启动器类工具的主流交互语义。
- 系统默认应用异常仍会导致后端打开失败；本次不新增错误反馈 UI，后续可单独处理。
