## Context

QuickFox 的搜索结果已经由 Rust core/Provider 返回统一的 `mainAction` 和 `secondaryActions`。文件、目录、应用结果的主动作当前都是 `openPath`，后端 `execute_action` 通过 Tauri opener 交给当前平台默认处理；右键菜单负责次要动作，例如复制路径、打开所在目录、选择打开方式。

当前前端结果行只在鼠标悬停时更新选中项，并在右键时打开动作菜单；左键单击没有执行路径。Enter 的执行路径只绑定在搜索输入框的 `onKeyDown` 上，因此用户点击结果后再按 Enter 可能不会触发主动作。

## Goals / Non-Goals

**Goals:**

- 鼠标左键单击结果行与 Enter 激活当前选中结果使用同一个主动作语义。
- 文件夹、文件、应用、网页搜索、计算器、命令等结果继续由后端返回的 `mainAction` 决定如何执行。
- 保持跨平台打开逻辑集中在 Rust core/Tauri opener，不把平台判断或文件类型关联规则放到前端。
- 保持右键菜单作为次要动作入口。

**Non-Goals:**

- 不新增第三方插件 API 或 Provider 扩展点。
- 不改变索引、排序、结果生成、文件扩展名识别或系统默认应用配置。
- 不为打开失败新增完整错误提示流程；本次只修正激活入口。

## Decisions

1. **统一激活入口而不是按类型在前端分支。**
   前端新增或提炼 `activateResult(result)` 入口，Enter 和左键单击都调用它。该入口只读取结果上的 `primaryAction`，不根据 `kind` 或路径扩展名自行决定动作。这样可以复用现有 Provider/Action 边界，并避免前端和 Rust core 的动作语义分叉。

2. **保留 Rust core 作为跨平台动作边界。**
   文件、目录和应用结果继续走 `openPath`，由 Tauri opener 调用平台默认处理。macOS 使用默认打开方式，Windows 使用 Shell 关联，Linux 使用桌面环境/xdg 关联。前端只负责请求执行动作。

3. **左键单击立即执行，右键只打开菜单。**
   结果行 `onClick` 执行该行主动作；`onContextMenu` 保持打开次要动作菜单并阻止默认菜单。左键执行前更新当前选中项，保证视觉状态和执行对象一致。

4. **测试优先覆盖行为契约。**
   前端测试先覆盖文件、目录和应用结果左键单击的主动作，以及 Enter 和左键对同一结果执行同一动作。现有 Rust 打开动作测试不需要重复平台打开细节。

## Risks / Trade-offs

- **单击即执行可能让误点成本变高。** → 这是启动器类工具的常见语义；右键菜单仍保留次要动作，悬停仅改变选中态。
- **系统默认应用异常仍可能导致打开失败。** → 本次保持现有后端错误返回；后续可单独增加执行失败反馈。
- **结果行内未来若加入按钮，点击冒泡可能触发主动作。** → 当前结果行没有内嵌主按钮；后续新增交互控件时应在控件内阻止冒泡。

## Migration Plan

1. 为当前前端行为添加失败测试。
2. 提炼统一结果激活函数并接入左键单击。
3. 运行前端测试、TypeScript/ESLint/Prettier 检查。
4. 不需要数据迁移或配置迁移；回滚时移除结果行 `onClick` 和对应测试即可。

## Open Questions

无。维护者已确认左键单击应立即执行主动作，Enter 执行当前选中项的同一主动作。
