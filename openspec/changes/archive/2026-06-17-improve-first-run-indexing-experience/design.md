## Context

上一轮索引优化已经引入 `ignore::WalkBuilder`、索引阶段、SQLite 快照、内容索引和 watcher。但当前短板仍在首次 Windows 体验：配置中常见的 `C:\Users` 与 `D:\` 都可能是巨大目录；QuickFox 仍使用普通目录遍历而不是 Everything 的 NTFS MFT/USN 技术，因此不能假设大范围扫描也会瞬间完成。

当前实现还存在两个产品语义落差：

- 设置页暴露了 `fast` / `balanced` / `complete`，但后端尚未用该配置改变扫描范围或阶段策略。
- 后台刷新按阶段执行，但阶段完成后会保存完整聚合快照并更新内存索引；最终完成时还会构建内容索引。这些重量级工作集中发生时，用户会感到卡顿。

索引完成后的输入搜索也有独立卡顿风险：前端对每个 `query` 变化立即调用 Tauri `search`；Rust 搜索路径会为本次查询构建 ProviderRegistry，并把 `SearchIndex` clone 给 FileProvider。大索引下，这会把“打一字”放大成“大索引 clone + 线性匹配 + 排序/结果回写”，即使索引已经建好也会卡。

## Goals / Non-Goals

**Goals:**

- 首次启动时优先让启动器、托盘、非文件 Provider 和高价值文件搜索可用。
- 让性能模式具备明确、可测试的行为差异。
- 降低阶段边界的 IO 和 CPU 峰值，减少“索引完成一段就卡一下”的体感。
- 将内容索引从首次 name/path 可用路径中拆出去，作为后台低优先级阶段。
- 降低连续输入时的每键查询成本，避免过期搜索结果覆盖更新输入。
- 保留现有配置、快照和搜索能力，不做破坏性迁移。

**Non-Goals:**

- 不接入 Everything、Windows Search、NTFS USN/MFT 或系统级索引服务。
- 不重写搜索排序、查询语法或文件 Provider 架构。
- 不在本次引入新的异步搜索服务进程或独立索引 daemon。
- 不承诺所有大盘在短时间内完整索引完成；短期目标是可用性和可控性。
- 不新增第三方插件 API。

## Decisions

1. **性能模式驱动索引计划。**
   - `fast`：只跑应用入口和用户热路径，不自动补扫大根目录；适合希望快速启动且手动控制范围的用户。
   - `balanced`：先跑应用入口和热路径，再后台补扫用户配置的大根目录；默认模式。
   - `complete`：跑完整配置范围和可选补全阶段，适合愿意等待完整结果的用户。
   - 这样比新增更多开关更容易理解，也让现有 UI 不再是空配置。

2. **把“快速可用”和“完整补全”分成不同阶段语义。**
   - 快速阶段完成后，name/path 搜索可立即使用已收录条目。
   - 后台补全阶段继续扫描 `D:\` 等大根；状态应表达“文件搜索已部分可用，仍在补全”。
   - 这比等待所有配置目录完成后才宣布可用更贴近启动器体验。

3. **阶段进度更新轻量化。**
   - 阶段中或阶段边界可以更新内存索引和状态，但完整 SQLite 快照写入应节流或只在高价值阶段/最终阶段执行。
   - 避免对不断增长的聚合条目每个阶段重复写全量批次。
   - 失败时仍应保留最近成功快照，不因本次补全失败丢失可用搜索。

4. **内容索引延后到 name/path 之后。**
   - 首次基础文件搜索不等待 Tantivy build。
   - 内容索引使用单独状态或子阶段表达，不覆盖基础文件索引可用状态。
   - 用户没有配置内容索引目录或没有使用 `content:` 时，不应让内容索引拖慢首次 name/path 体验。

5. **体验反馈要诚实而不打扰。**
   - 启动器可显示轻量文案，例如“文件搜索已部分可用，正在补全 D:\”。
   - 设置页显示当前模式、阶段、当前 root、已扫描/收录/跳过/失败。
   - 普通文件查询无结果时，如果补全仍在进行，应提示“可能仍在索引该范围”，并提供打开设置/切换模式入口。

6. **搜索输入路径要避免每键重量级工作。**
   - Rust 搜索命令不应为每次查询 clone 整个 `SearchIndex`；FileProvider 应借用共享索引、Arc 指针或等价轻量引用。
   - ProviderRegistry 可以按查询构建，但其中的大索引引用必须是 O(1) 级成本。
   - 前端应对文件搜索输入做短延迟节流或 request sequencing；过期查询结果不能覆盖较新的输入。
   - 查询耗时应可测试：大索引下连续普通查询应保持 bounded candidate work，且不发生与条目数成正比的大对象复制。

## Risks / Trade-offs

- [Risk] `fast` 模式可能让用户以为某些文件丢失。→ 文案明确“只索引应用和常用目录”，设置页提供切换到 balanced/complete。
- [Risk] 减少阶段快照写入可能导致崩溃后丢失部分本轮进度。→ 保留最近完成快照；快速阶段完成后可保存一次轻量快照，后台补全最终再保存完整快照。
- [Risk] 内容索引延后会让 `content:` 初次查询暂时不可用。→ `content:` 查询返回明确状态反馈，说明内容索引仍在准备或未启用。
- [Risk] 大根目录仍可能长时间占用磁盘。→ 后台补全应低优先级、可取消/可跳过，并允许用户从设置页收窄范围。
- [Risk] 输入节流会让结果显示略晚。→ 使用很短的延迟并在输入为空、命令模式、非文件 Provider 路径保持即时反馈；优先保证键入流畅。
- [Risk] 共享索引引用如果设计不当会引入锁竞争。→ 搜索只读路径应尽量缩短锁持有时间，或把不可变索引放入轻量共享结构。
