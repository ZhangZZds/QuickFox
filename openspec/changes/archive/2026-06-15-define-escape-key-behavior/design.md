## Context

QuickFox 启动器当前通过搜索输入框的 `onKeyDown` 处理 Esc、方向键和 Enter。这个设计在输入框始终聚焦时有效，但最近搜索结果支持左键激活后，用户会更自然地点击结果行、打开动作菜单或切换到设置页控件。此时 Esc 不一定经过输入框 handler，导致“按 Esc 没反应”。

设置页也有局部状态，例如全局唤醒快捷键录制和网页搜索新增向导。Esc 在这些状态里更应该取消局部操作，而不是关闭整个窗口或完全无效。

## Goals / Non-Goals

**Goals:**

- 为 Esc 建立清晰的优先级：局部状态优先，普通启动器状态关闭启动器。
- 让 Esc 在焦点离开搜索输入框后仍然可用。
- 避免 Esc 误执行搜索结果、命令或输入历史记录。
- 保持设置页常态稳定，不用 Esc 直接关闭设置窗口。

**Non-Goals:**

- 不重做完整键盘导航系统。
- 不改变 Enter、方向键、Shift 历史模式等既有语义，除非 Esc 优先级需要关闭局部状态。
- 不新增平台层窗口关闭命令。

## Decisions

1. **使用统一 Esc handler。**
   在 `App` 内提炼 `handleEscapeKey()`，集中判断状态并执行第一个匹配动作。输入框 `onKeyDown` 继续处理方向键、Enter 和 Shift，但 Esc 分支委托统一 handler。

2. **在 document 级别兜底监听 Esc。**
   使用 `useEffect` 注册 `keydown`，仅处理 `event.key === "Escape"`。这样结果项、菜单按钮、快捷键录制按钮或设置页控件获得焦点时，Esc 仍能触发统一逻辑。输入框触发时通过 `event.defaultPrevented` 避免重复处理。

3. **局部状态优先级固定。**
   优先级为：快捷键录制 > 动作菜单 > 历史模式 > 设置页弹层 > 启动器关闭 > 设置页常态无动作。该顺序让正在进行的局部交互先被取消，避免直接关闭更大的上下文。

4. **保持命令预览为普通启动器状态。**
   命令预览没有自己的弹层；Esc 在命令预览中关闭启动器，不执行命令、不记录历史。

## Risks / Trade-offs

- **document 级监听可能和输入框 handler 重复触发。** → handler 调用 `preventDefault()`，document 监听检查 `defaultPrevented` 后跳过。
- **Esc 不关闭设置页可能与部分系统偏好不同。** → 设置页常态可能包含未保存编辑，保守保留上下文；窗口关闭继续由系统窗口控件或托盘生命周期管理。
- **未来新增弹层需要接入优先级。** → `handleEscapeKey()` 作为集中入口，后续状态可在这里扩展。

## Migration Plan

1. 添加失败测试覆盖焦点不在输入框时 Esc 关闭启动器。
2. 添加失败测试覆盖动作菜单、历史模式、快捷键录制和设置页向导的 Esc 优先级。
3. 实现统一 Esc handler 和 document 级兜底监听。
4. 运行前端测试、格式、lint、build 和全量检查。
