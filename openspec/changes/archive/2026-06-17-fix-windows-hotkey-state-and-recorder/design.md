## Context

QuickFox 当前用 `keytap` 监听低层键盘事件，再由 Rust core 的 `HotkeyState` 判断 `Shift+Shift` 或 `Modifier+Key`。组合键状态机只维护 `pressed_modifiers`，如果 Windows 桌面环境没有送达修饰键释放事件，后续普通 Space 仍会被判断为已满足 `Shift+Space`。设置页录制器使用前端 DOM `keydown`，遇到 `Alt+Space` 这类系统保留组合键时可能收不到目标按键事件，用户只能在后续真实使用时发现不可用。

## Goals / Non-Goals

**Goals:**

- 让组合键只在一个短暂、连续的按键序列内触发，降低修饰键状态残留导致的误唤醒。
- 在设置页录制阶段识别高风险组合键并显示明确错误。
- 增加能模拟键盘事件序列的自动化测试，让类似问题先在测试中暴露。

**Non-Goals:**

- 不切换到第三方插件 API 或新增平台原生全局快捷键 Adapter。
- 不承诺自动化覆盖真实 Windows 桌面系统保留快捷键的全部行为；这仍需 Windows 手工验收补充。
- 不改变默认 `Shift+Shift` 唤醒行为。

## Decisions

1. **给组合键增加按下窗口和一次性触发约束。**
   - 当前状态机会无限期保留 `pressed_modifiers`，这是误触根因。
   - 新逻辑记录最近修饰键按下时间，只有 wake key 在短窗口内到达才触发；触发后清空修饰键状态，避免同一次按住修饰键期间重复触发。
   - 备选方案是仅在任意非目标键按下时清空状态，但无法覆盖“释放事件丢失后直接按 Space”的用户场景。

2. **前端录制器拒绝已知系统保留组合键。**
   - Windows `Alt+Space` 通常打开窗口系统菜单，DOM 层可能无法稳定捕获。
   - 设置页应给出“该组合键可能被系统占用，请换用 Control/Shift/Command 加普通键”的错误，而不是让用户保存一个后续不可用的配置。
   - 备选方案是允许保存并只写文档提示，但这会把发现成本继续留给用户。

3. **用可模拟事件序列做主动探索。**
   - Rust 单元测试覆盖 `KeyDown/KeyUp` 序列，包括释放事件丢失、慢速组合、重复 Space。
   - 前端测试覆盖录制器按键事件和错误提示。
   - Windows 真实桌面行为仍通过手工 QA 或后续 UI 自动化脚本补足，因为系统级快捷键截获不能完全由 jsdom 或 macOS CI 代表。

## Risks / Trade-offs

- [Risk] 组合键窗口过短会让慢速按键用户触发失败。→ 采用与双击 Shift 一致的 500ms 窗口，并用测试锁定。
- [Risk] 保留组合键列表不完整。→ 先覆盖用户已遇到的 `Alt+Space`，后续发现再以测试和文档增补。
- [Risk] 低层监听库在 Windows/Linux 的事件语义不同。→ 把纯状态机规则放到跨平台单元测试，真实桌面差异进入 Windows/Linux QA 清单。
