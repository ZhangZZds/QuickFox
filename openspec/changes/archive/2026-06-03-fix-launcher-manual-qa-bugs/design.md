## Context

当前 QuickFox 已有 MVP：Tauri 前端窗口、Rust core、文件索引、Provider、
Action dispatcher、配置和 SQLite 历史。但手工测试发现多个问题集中在“启动器
是否像桌面工具一样可靠可控”：快捷键没有切换语义，搜索结果噪音太大，设置
入口无效，网页搜索无法按预期触发，历史语义和维护者原意不一致。

本变更以 macOS 测试发现的问题为入口，但设计必须覆盖 Windows 和 Linux。
自动化测试负责覆盖可抽象的核心行为；真实桌面行为仍需要手工验收，尤其是
全局快捷键、窗口置前、托盘菜单和系统默认应用打开。

## Goals / Non-Goals

**Goals:**

- 让 `Shift+Shift` 成为显示/隐藏切换，而不是只尝试显示。
- 普通搜索不返回明显低相关结果，尤其不显示应用包和工具内部资源噪音。
- 把应用作为一等结果类型处理，并为三端定义应用识别规则。
- 让网页搜索通过 `g 1234`、`bd 1234` 这类空格前缀稳定触发。
- 设置入口、设置页分类、索引刷新和输入历史符合用户预期。
- UI 修复以启动器工具体验为目标：紧凑、无多余空白、菜单位置正确。

**Non-Goals:**

- 不实现文件内容索引。
- 不开放第三方插件 API。
- 不实现后台文件系统 watcher 的实时全量监控；增量刷新先通过可触发的刷新
  API 和索引状态比较实现。
- 不把 macOS 手工结果当成 Windows/Linux 桌面行为完成证据。

## Decisions

### 使用显式窗口状态机处理 `Shift+Shift`

窗口状态按 `hidden`、`visible-unfocused`、`visible-focused` 建模。全局快捷键
触发时，如果窗口不可见或在后台，则显示、置前并聚焦输入框；如果窗口已经
可见，则隐藏。这样托盘“显示 QuickFox”和双击 Shift 可以共享同一套状态转换。

备选方案是继续每次调用 show/focus。它无法表达“再次触发关闭”，也容易在
不同平台出现窗口在后台但状态不一致的问题。

### 普通搜索使用阈值和噪音过滤

索引仍然只存名称和路径，但普通模糊搜索必须有最低匹配质量。没有足够字符
命中或匹配分数低于阈值的结果不返回。显式正则搜索仍按正则规则返回匹配项。

扫描阶段默认排除应用包内部、构建产物、缓存和系统隐藏噪音目录。对于应用包
或快捷方式，只把应用入口作为结果：macOS `.app`，Windows `.exe`/`.lnk`，
Linux `.desktop`。跨平台规则放在 Rust core 的类型识别边界中，而不是前端
凭路径字符串判断。

### 排序先按结果类型，再按相关性和历史

结果类型优先级为应用程序 > 文件 > 目录。类型相同后再比较匹配质量、精确
子串、路径深度和使用历史。这样“打开应用”的启动器主路径更稳定，同时不会
牺牲文件/目录搜索能力。

### 网页搜索采用空格前缀语法

查询解析器将 `prefix query` 识别为网页搜索，其中 prefix 必须完全匹配配置
中的网页搜索前缀，且 query 非空。默认配置至少包含 `g` 和 `bd`。`g: query`
不作为本变更的主路径；如需兼容旧语法，可作为非阻塞兼容能力，但测试和文档
以空格形式为准。

### 输入历史按“确认执行”记录

历史记录从“命令历史”升级为“输入历史”。只有用户按 Enter 并成功执行主动作
后才记录输入，包括文件、目录、命令和网页搜索。普通输入、关闭窗口、Esc 或
只移动选择不记录。默认最多 15 条，上/下方向键在搜索框内召回最近输入；当
结果列表打开时，需要避免和结果选择冲突，优先规则由 UI 状态决定。

### 设置属于托盘和独立设置视图

快速启动窗口只保留搜索和结果，不显示设置按钮。设置入口放在托盘右键菜单。
设置页按“搜索与索引”“网页搜索”“历史”“命令执行”“外观与窗口”分组，给后续
扩展保留空间。刷新索引是“搜索与索引”分组中的明确动作。

## Risks / Trade-offs

- **风险：不同平台应用识别规则不完全一致。** → 将识别逻辑集中到 Rust core，
  用平台分支测试覆盖 `.app`、`.exe`、`.lnk`、`.desktop`。
- **风险：搜索阈值过高导致找不到弱匹配。** → 通过单元测试覆盖不存在查询
  不返回噪音、合理缩写仍可返回目标两类场景。
- **风险：增量刷新复杂度膨胀。** → 第一阶段只实现基于路径状态比较的触发式
  增量刷新，不引入常驻 watcher。
- **风险：方向键同时承担历史召回和结果导航。** → UI 明确状态：输入框历史
  模式与结果导航模式分开测试，避免按键语义互相覆盖。
- **风险：窗口置前行为受平台权限影响。** → 自动化测试状态机，真实置前由
  macOS/Windows/Linux 手工验收清单确认。

## Migration Plan

现有配置需要兼容旧字段。命令历史相关配置迁移为输入历史配置；若旧用户只
有命令历史数据，可以保留为输入历史的子集。网页搜索配置保留前缀和 URL
模板结构，但默认语法和文档改为 `prefix query`。

实现时应先补测试和 Tauri contract，再修改 Rust core 和前端。若某个平台
桌面行为无法在当前机器确认，应在手工验收文档中留下待验收项。

## Open Questions

无阻塞问题。搜索阈值的具体分数、默认排除目录列表和历史导航 UI 细节可在
TDD 实现阶段通过测试样例细化。
