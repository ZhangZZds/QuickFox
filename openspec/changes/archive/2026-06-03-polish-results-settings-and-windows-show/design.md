## Context

当前结果列表使用两列 grid：标题占剩余空间，路径列为 `auto` 且有 `max-width: 42%`。当标题重复、路径很长时，路径列位置会随内容变化，且只显示路径开头，用户很难判断命中的是哪个目录下的文件。设置页的保存按钮位于表单内容末尾，切换分区后看起来像每个页面都有一枚独立按钮。Rust 托盘“显示 QuickFox”直接调用 `show_main_window`，没有更新窗口状态机，也没有针对 Windows 置前做更稳的显示序列。

## Goals / Non-Goals

**Goals:**

- 让结果列表在重复文件名场景下可扫描、可对齐、可确认命中路径。
- 让选中行在键盘移动时有明显视觉变化，且测试覆盖选中状态。
- 让设置页索引信息完整可见，包括条目数、状态、配置文件位置和索引快照位置。
- 将保存设置改成设置页级别操作，放在左侧导航下方统一管理。
- 修复 Windows 托盘“显示 QuickFox”无法可靠显示/聚焦的问题。

**Non-Goals:**

- 不引入第三方 UI 组件库。
- 不改变 Provider 结果排序和搜索算法。
- 不实现第三方插件 API。
- 不在本变更中重新设计整套视觉品牌。

## Decisions

1. 结果行改为稳定三段布局：主标题区、路径摘要区、类型/辅助信息区可后续扩展。当前实现先使用 `minmax(220px, 32%) minmax(0, 1fr)`，保证标题和路径列稳定对齐。
   - 备选：标题和路径上下两行。优点是移动端友好，缺点是桌面列表密度下降；因此只在窄宽度下采用上下布局。

2. 路径摘要由前端展示函数生成，完整路径仍来自后端 `detail`。摘要格式保留起始根路径和结尾 2-3 段，中间用省略号表示，例如 `/Users/frankzhang/.../QuickFox/README.md`。
   - 备选：后端直接返回摘要。缺点是展示策略会污染 Provider 统一结果；因此保持后端返回完整 detail，前端负责显示。

3. 完整路径通过原生 `title` tooltip 暴露，同时保留 `aria-label`，不新增复杂浮层。
   - 备选：自定义 tooltip。优点是样式统一，缺点是需要处理定位、遮挡和可访问性；本轮先使用浏览器原生能力。

4. 选中态采用背景、左侧强调条、轻微阴影和标题颜色组合，不依赖半透明浅色背景单一信号。键盘移动继续通过 React state 更新 `aria-selected`，测试验证所选项和 CSS class/attribute。

5. 设置页使用左侧导航 + 左侧固定操作区 + 右侧内容区。保存按钮只出现一次，分区内容不再重复承载保存动作。

6. Rust 新增应用路径信息查询命令，返回配置文件路径和索引快照路径。设置页加载后显示这些路径；无法确定时显示“未找到”或“尚未创建”。

7. 托盘“显示 QuickFox”复用统一显示并同步窗口状态，显示序列包含 `show -> unminimize -> set_focus`。如果 Windows 上 Tauri `set_focus` 仍受系统限制，手工验收记录真实行为并补 issue。

## Risks / Trade-offs

- [Risk] 路径摘要对 Windows 盘符和 UNC 路径处理不完整 → 使用跨平台分隔符解析测试覆盖 `C:\Users\...` 和 POSIX 路径。
- [Risk] 原生 `title` tooltip 样式不可控 → 本轮目标是可确认完整路径，不把 tooltip 视觉作为核心品牌元素。
- [Risk] Windows 置前受系统焦点抢占限制 → 代码层面统一显示/聚焦路径，并在 Windows 手工验收中记录系统限制。
- [Risk] 设置页布局变化可能影响小窗口 → CSS 使用响应式 grid，小宽度下保存操作回到内容流顶部或底部。
