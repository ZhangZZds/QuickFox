## Why

macOS 手工测试暴露出 QuickFox MVP 的核心启动器体验还不稳定：窗口唤起、
搜索相关性、网页搜索、设置入口、索引刷新、输入历史和结果 UI 都存在用户
可见问题。现在需要用一个稳定化变更统一收口这些缺陷，并把跨平台行为写入
规格，避免只按 macOS 现象局部修补。

## What Changes

- 修复 `Shift+Shift` 行为：隐藏或后台时显示并置前，已显示时再次触发隐藏。
- 改善普通搜索相关性，避免不存在查询返回明显无关路径。
- 默认排除应用包、系统缓存和开发工具内部资源的噪音，同时保留应用本身可被
  搜索启动。
- 明确跨平台应用识别：macOS `.app`、Windows `.exe`/`.lnk`、Linux
  `.desktop` 作为应用结果。
- 调整排序规则：应用程序优先，其次文件，再其次目录；同类结果再结合匹配
  质量、路径信号和历史。
- 修复网页搜索触发方式，使用空格前缀，例如 `g 1234` 和 `bd 1234`。
- 修复设置入口：快速启动窗口不显示设置按钮，设置从托盘菜单打开。
- 设置页按功能分类管理，并支持手动刷新索引。
- 明确索引基于持久历史索引查询，并新增增量刷新能力。
- 将“命令历史”升级为“输入历史”：仅记录用户按 Enter 成功执行的文件、
  目录、命令和网页搜索输入，默认保留最近 15 条，上/下方向键可召回。
- 修复结果列表 UI：空搜索不显示多余底部区域，右键菜单靠近目标结果显示，
  搜索列表不出现割裂的系统滚动条。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `launcher-shell`: 修改窗口显示/隐藏、托盘设置入口、空状态、动作菜单定位、
  设置页分类和列表滚动表现。
- `search-index`: 修改索引过滤、应用类型识别、搜索相关性、排序规则，并新增
  增量刷新语义。
- `query-providers`: 修改网页搜索前缀语法为 `prefix query`，并要求配置
  `g`/`bd` 等搜索引擎可触发 URL 结果。
- `configuration-and-history`: 将命令历史改为确认执行过的输入历史，并保留
  清空、关闭和最大条数设置。

## Impact

- 影响 Rust core 的查询解析、Provider、Ranker、索引扫描、存储和配置模型。
- 影响 Tauri 命令、窗口显示/隐藏逻辑、托盘菜单和设置窗口打开逻辑。
- 影响 React 启动器 UI、结果菜单、设置页布局、历史导航和相关测试。
- 需要补充 macOS 手工验收记录，并通过单元测试覆盖 Windows/Linux 的路径、
  应用识别和终端/URL 构造等可自动化逻辑。
