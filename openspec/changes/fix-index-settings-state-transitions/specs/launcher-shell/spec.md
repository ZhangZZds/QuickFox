## MODIFIED Requirements

### Requirement: 设置页统一保存操作

系统 SHALL 在设置页提供单一的保存设置入口，不在每个设置分区内容末尾重复展示保存按钮；统一入口 MUST 显示草稿是否未保存以及保存请求的进行、成功或失败状态。

#### Scenario: 切换设置分区时保存入口保持稳定

- **WHEN** 用户在索引、网页搜索、历史、命令安全和外观分区之间切换
- **THEN** 保存设置按钮仍位于统一操作区，且页面内容区不重复出现额外保存按钮
- **AND** 未保存状态不因切换分区而丢失

#### Scenario: 保存请求状态可见

- **WHEN** 用户点击保存设置
- **THEN** 保存入口立即显示保存中并避免重复提交同一草稿
- **AND** 配置持久化成功后显示配置已保存
- **AND** 配置校验或写入失败时显示可操作错误

## ADDED Requirements

### Requirement: 设置页区分配置保存与索引应用

系统 SHALL 在索引设置中分别展示 desired config 的保存状态和后台 index revision 的应用状态，状态至少包含应用中、已应用、部分失败和失败；后台失败不得让控件静默恢复为旧值。

#### Scenario: 保存 balanced 后关闭并重开设置

- **WHEN** 用户从 `fast` 选择 `balanced` 并收到配置已保存反馈，然后在后台补全完成前关闭并重开设置
- **THEN** 性能模式控件仍显示 `balanced`
- **AND** 索引区域显示后台应用中或部分可用状态

#### Scenario: 后台应用失败

- **WHEN** 配置已保存但后台 index revision 因 root 或存储错误失败
- **THEN** 设置页保留用户已保存字段值
- **AND** 显示失败摘要及“重试索引”或“修改范围”动作

#### Scenario: 保存后无需再次刷新

- **WHEN** 用户成功保存影响索引语义的设置
- **THEN** 系统自动安排后台应用
- **AND** 帮助文本不要求用户再次点击刷新才能生效
- **AND** 手动刷新入口被描述为恢复或重新校准动作

### Requirement: 整盘索引设置显示风险

系统 SHALL 在 Windows 用户配置盘符根目录时明确提示首次补全、磁盘 I/O、索引存储和不可访问目录风险，不得把整盘范围描述为与普通子目录等价的轻量操作。

#### Scenario: 添加 D 盘根目录

- **WHEN** Windows 用户在索引目录中填写 `D:\` 或 `D:/`
- **THEN** 设置页显示优先选择具体子目录的风险说明
- **AND** 不阻塞用户保存明确选择
