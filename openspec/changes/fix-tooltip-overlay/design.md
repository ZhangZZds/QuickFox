## Context

`HelpIcon` 将提示内容放在按钮的同一 DOM 子树内，并以绝对定位向上展开。设置内容区必须独立
滚动，因而它的溢出裁切会截断该提示。仅调整 `z-index` 无法跨越裁切边界；取消滚动则会破坏长
设置页的可用性。

## Goals / Non-Goals

**Goals:**

- 在所有滚动上下文中完整显示帮助文本。
- 支持鼠标和键盘，且在窗口边缘稳定定位。
- 保持既有帮助文字、问号按钮和设置布局不变。

**Non-Goals:**

- 不重做设置页整体视觉样式。
- 不引入第三方 tooltip 依赖，也不改变 Tauri 窗口尺寸策略。

## Decisions

### 通过 portal 作为窗口级浮层渲染

帮助按钮仍位于字段标题中，浮层渲染至 `document.body`，用按钮的矩形计算 `position: fixed`
坐标。这样浮层脱离滚动容器的裁切上下文；选择它而非单纯增加 `z-index`，因为裁切不会被
`z-index` 覆盖。

### 采用可用空间驱动的双向定位

打开浮层时优先放在锚点上方；上方空间不足就向下。左右位置钳制到统一的视口边距中，避免长
路径或说明溢出窗口。`scroll`（capture）和 `resize` 事件触发重算，保证内容滚动或缩放后仍对齐。

### 保留语义与交互边界

按钮继续提供可访问名称；打开时以 `aria-describedby` 关联唯一的 `role="tooltip"` 元素。
鼠标离开、焦点移走或组件卸载时移除浮层。浮层不接收指针事件，避免鼠标跨越触发按钮与浮层时
造成闪烁。

## Risks / Trade-offs

- [测试环境缺少真实布局] → 将定位计算提取为纯函数，单测覆盖方向和边界；再做桌面手工验收。
- [快速滚动时位置瞬时更新] → 监听 capture 滚动事件并仅在提示打开时更新。
- [portal 增加 DOM 复杂度] → 保持单一 `HelpIcon` 封装，调用方无需理解浮层实现。

## Migration Plan

前端热更新后即可生效，无配置和数据迁移。若发现平台兼容问题，可回退此独立前端变更；旧实现
不会影响持久化数据。
